Rectangular execution

The planner checks index ranges, coefficient visits, and live workspace before the executor forms padded blocks. The multiplication routines combine each term in its coefficient domain and accumulate the output blocks.

NineFourths.ExecutionInfeasible — Type
ExecutionInfeasible
ExecutionInfeasible(reason, input_size, input_shape, block_side, limit)

The requested multiplication could not run a scheme layer. The reason symbol identifies the failed check. The input_shape::NTuple{3,Int} gives (m, k, n) for an m×k by k×n product. The input_size is the common Int dimension for square inputs of equal size and nothing otherwise. The block_side may be an integer, a symbolic WitnessSide, or nothing for a zero dimension. The limit is the relevant resource bound as a BigInt or nothing.

Block recursion and accumulation

NineFourths._accumulate_form! — Method
_accumulate_form!(form, source, scheme, domain, term, leg, side,
                  active_rows, active_columns)

Add one scheme input form from source to the one-based child buffer form.

Select the left or right input form of term with leg equal to 1 or 2. The square block grid has side side, and the active dimensions count the block rows and columns containing source entries. Blocks beyond the source index ranges contribute zero. The scalar domain comes from _field_inputs.

Multiply two one-based matrices using conventional dot products.

NineFourths._scheme_product — Method
_scheme_product(A, B, scheme, domain, zero_value, side, rank)

Multiply two one-based matrices using one scheme layer and any admissible child layers.

The layer uses rank terms and a block grid of side side. It constructs child input forms in the selected domain and uses conventional multiplication when the child dimensions reach the recursion limit. The returned Matrix{Any} can hold native scalars and formal phase work values pending output conversion.
